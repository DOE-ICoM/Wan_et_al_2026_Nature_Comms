# Wan et al. (2026) — Coastal Flood Impact Sensitivity in the Eastern United States 

Code and data accompanying **Wan et al., 2026 (*Nature Communications*)**.
This repository provides the end-to-end workflow for estimating **building-level flood
damage losses, inundated population, and census-tract aggregated impacts** from storm
surge scenarios across coastal U.S. study blocks.

The pipeline combines:

- 10 m raster inputs for building footprints/heights (Microsoft Building Footprints,
  MSBF), per-building IDs, census tracts, population, and modeled surge depths; and
- Census-tract median home prices and household counts

to produce building-level damage CSVs, tract-level property-value tables, and a merged
multi-scenario wide-format dataset used for the figures in the paper.

Study blocks are numbered `01`–`15` (block `06`, Florida keys, is intentionally 
skipped — see note below). Surge heights are encoded in decimeters (`05`, `10`, 
…, `50` → 0.5 m to 5.0 m). Attenuation scenarios are named `Att50`.

> **Note on Block 06 (Florida keys).** Block 06 covers only a very small land
> area focused on Key West, FL, where the Microsoft Building Footprints (MSBF)
> building-height coverage is extremely sparse. Even after applying our
> height-interpolation procedure, a large fraction of buildings in this block
> remained without a usable height value, which prevented reliable downstream
> damage and exposure calculations. Block 06 is therefore excluded from all
> processing loops and from the archived input dataset on MSD-LIVE.

## Data availability

All input datasets required to reproduce the analysis in this repository
are archived on the **MSD-LIVE Data Repository**:

> Wan, H. et al. (2026) *Wan_et_al_2026_Nature_Comms (Version v1) [Data set].*
> MSD-LIVE Data Repository. https://doi.org/10.57931/17427421

After downloading the archive, extract it into the repository root so that
the folder layout matches the structure shown above, i.e. all files are
placed under `Data/Input_data/`. The archive contains the following
components:

| Sub-folder | Contents | Format | Notes |
|---|---|---|---|
| `MSBF/` | Per-block height-filled residential building-height rasters (`Block<BB>-Buildings.tif`) at 10 m resolution; values in meters, 0 outside buildings. | GeoTIFF | Preprocessed products generated by `Scripts/building_fill.py` (see Workflow step 0). Users do **not** need to re-run `building_fill.py` to reproduce the paper's results. |
| `Building_IDs/` | Per-block unique integer building-ID rasters (`Block<BB>-Building_IDs.tif`) at 10 m resolution, co-registered with the MSBF rasters. | GeoTIFF | Used to accumulate per-building damage and inundated population. |
| `Census_tract/` | Per-block census-tract ID rasters (`CT<BB>.tif`) at 10 m resolution, and matching attribute tables (`CT<BB>.csv`) with columns `tract_id, GEOID, median_home_price, total_homes`. | GeoTIFF + CSV | Local tract IDs link raster pixels to the attribute table via `tract_id`; `GEOID` is the standard 11-digit U.S. Census tract identifier. |
| `Pop/` | Per-block 10 m population rasters for 2020, 2050, and 2100 (`Block<BB>-Building-Pop-<YYYY>_10m.tif`). | GeoTIFF | Per-pixel population counts allocated to residential buildings. |
| `Surge/Block-<BB>/` | Per-block storm-surge inundation-depth rasters at 10 m resolution for 10 surge heights (0.5–5.0 m, encoded as `05`–`50` decimeters) under the `Att50` attenuation scenario (`Surge-<BB>_<HH>-Att<AA>.tif`). | GeoTIFF | Flood depth in meters; one raster per block × surge-height × attenuation combination. |
| `CBSA/` | East-coast Metropolitan Statistical Area (MSA) polygons (`tl_2025_us_cbsa/East_coast_msa.*`) and a CBSA-to-county FIPS crosswalk (`cbsa_to_county_fips.json`). | Shapefile + JSON | Used by `MSA_inundated_area_calculation.R` to compute per-MSA inundated area. |

Study blocks are numbered `01`–`15`, excluding block `06` (Florida Keys);
see the note above for details. All rasters within a given block are
co-registered on the same 10 m grid, and the Python pipeline validates
this at load time.

All outputs under `Data/Output_data/` are produced by the scripts in this
repository and are not required to be downloaded separately. The raw
Microsoft Building Footprints and OpenStreetMap inputs to the preprocessing
step `Scripts/building_fill.py` are **not** redistributed with the archive;
their original sources are listed under Workflow step 0.

## Inputs

All rasters within a given block are expected to be **co-registered on the same 10 m grid**
(the Python pipeline validates this at load time).

| Layer | File | Description |
|---|---|---|
| Building height | `MSBF/Block<BB>-Buildings.tif` | Building height in meters (0 outside buildings) |
| Building IDs | `Building_IDs/Block<BB>-Building_IDs.tif` | Unique integer ID per building |
| Census tracts | `Census_tract/CT<BB>.tif` | Local tract ID raster |
| Census attrs | `Census_tract/CT<BB>.csv` | Columns: `tract_id, GEOID, median_home_price, total_homes` |
| Population | `Pop/Block<BB>-Building-Pop-<YYYY>_10m.tif` | Per-pixel population (2020/2050/2100) |
| Surge depth | `Surge/Block-<BB>/Surge-<BB>_<HH>-Att<AA>.tif` | Flood depth (m) for surge/attenuation scenario |

Building height thresholds used throughout the pipeline:

- **LowRise** (`LowStory`): `< 5.5 m`
- **MedRise** (`MedStory`): `5.5 – 22.86 m`
- **HighRise** (`HighStory`): `> 22.86 m`

Depth–damage curves (percent damage vs. inundation depth) are hard-coded in
`Scripts/Building_level_impact.py` for single-story, two-story, and high-rise
buildings and are evaluated with a natural cubic spline, clamped at the knot range.

## Workflow

### 0. (Preprocessing) Height-fill the MSBF building rasters

```bash
python Scripts/building_fill.py
```

This preprocessing script generates the height-filled residential building
rasters (`Data/Input_data/MSBF/Block<BB>-Buildings.tif`) that are used by all
downstream steps. For each study block it:

1. Masks out non-residential buildings using OSM-derived non-residential
   parcel and building masks.
2. Fills missing residential building-height pixels from nearby valid heights
   using a median-of-neighborhood (or nearest-neighbor) search, with search
   distances that depend on an urban-area mask.
3. Merges the original MSBF residential height raster, a residential building
   fill raster (presence mask), and the neighbor-derived heights into a
   single filled building-height raster.

The raw Microsoft Building Footprints (MSBF) input data can be downloaded
from Microsoft's Global ML Building Footprints repository:

> https://github.com/microsoft/globalmlbuildingfootprints

The raw OpenStreetMap (OSM) land-use and building-footprint data used to
build the non-residential parcel/building masks can be downloaded as
regional OSM extracts from Geofabrik:

> https://www.geofabrik.de/data/download.html

The additional OSM-derived non-residential masks, urban masks, and raw MSBF
height rasters used as inputs to this script are intermediate preprocessing
products and are **not** redistributed with this repository. The script is
provided for methodological transparency / provenance; the resulting
height-filled rasters are already included under `Data/Input_data/MSBF/` so
that users can reproduce the downstream analysis without re-running this
step.

### 1. Building-level damage and inundated population

```bash
python Scripts/Building_level_impact.py
```

For each block × attenuation × surge-height combination, this:

1. Computes **global per-tract/per-type pixel counts, mean heights, and unique
   building counts** from the static layers (building height, building ID, tract
   raster).
2. Streams the surge raster in windows, classifies buildings by height,
   evaluates the appropriate depth–damage curve pixel-by-pixel, and accumulates
   per-building `damage_sum`, `pixel_count`, `inundated_population`, and a flag
   indicating whether the building was inundated.
3. Converts the damage percent to dollars using the tract's median home price,
   **volume-adjusted** for mid- and high-rise buildings relative to the tract's
   low-rise mean building volume.

Output: `Data/Output_data/Building_level_impact_results/building_damage_<block>_<surge>_Att<att>.csv`

with columns:

```
Building_ID, Census_Tract_ID, Building_Type,
Estimated_Building_Value, Damage_Loss_Dollars, Inundated_Population
```

### 2. Tract-level total property value

```bash
python Scripts/Total_property_value_by_CT.py
```

Produces `Data/Output_data/total_property_value_by_census_tract.csv` with
LowRise/MedRise/HighRise home counts, volume-adjusted unit values, and total
property value per GEOID.

### 3. Aggregate building-level results to census tracts (R)

```r
source("Scripts/Building_aggregated_to_census_tract.R")
```

For each surge height, this reads all per-block building damage CSVs,
sums damage dollars and inundated population by tract and by building type
(All / Low / Med / High), joins to each block's `CTXX.csv` for the GEOID, and
writes:

```
Data/Output_data/Census_tract_aggregation/Property_Value_and_Pop_CT_<HH>_dm_by_type.csv
```

### 4. Merge all surge-height scenarios into a wide-format table (R)

```r
source("Scripts/Merge_all_surge_height_results.R")
```

Combines every `Property_Value_and_Pop_CT_<HH>_dm_by_type.csv`, pivots to a
GEOID-indexed wide format, and renames columns (e.g. `A_loss_25` →
`A_25_50`, `A_pop_25` → `Pop_25_2020`) to match the format used by the figure
notebook.

Output: `Data/Output_data/Damage_and_Pop_by_CT_WIDE_FORMAT_by_type.csv`


### 5. Per-MSA inundated area (R, parallelized)

```r
source("Scripts/MSA_inundated_area_calculation.R")
```

For each surge height, this script mosaics all per-block surge rasters in
`Data/Input_data/Surge/Block-XX/`, reprojects the mosaic to Albers Equal Area
(EPSG:5070), and computes the total flooded area (km²) within each East-coast
MSA polygon from `Data/Input_data/CBSA/tl_2025_us_cbsa/East_coast_msa.shp`.
Results are written to:

```
Data/Output_data/total_flooded_area_all_msas.csv
```

The script is parallelized across surge heights with `foreach` + `doParallel`
(default `parallel::detectCores() - 4`) and caches intermediate rasters under
`Data/Temp/R_temp/`. 

### 6. Figures

Open `Scripts/Figure_plot.ipynb` in Jupyter/PyCharm and run top-to-bottom to
reproduce the paper figures from the merged wide-format CSV and ancillary
tables in `Data/Output_data/`.

## Notes and assumptions

- **Block 06 (Florida keys)** is deliberately excluded from all processing
  loops. This block covers only a very small land area focused on Florida keys,
  where Microsoft Building Footprints (MSBF) height coverage is extremely
  sparse; even after our height-interpolation step, most buildings
  remained without usable heights to support reliable downstream damage and
  population-exposure estimation.
- **Volume adjustment**: mid- and high-rise unit values are scaled by the ratio
  of their mean per-building volume to the low-rise mean per-building volume
  within the same tract, so damage dollars reflect building-type differences
  while anchoring to the tract's median single-family home price.
- **Paths**: the Python scripts resolve `PATH_BASE` relative to each script's
  own directory (`Scripts/data/input_data`). If your data lives at
  `Data/Input_data/` (as laid out above), adjust the `PATH_BASE` constant at
  the top of `Building_level_impact.py` and `Total_property_value_by_CT.py`
  accordingly, e.g.:
  ```python
  PATH_BASE = SCRIPT_DIR.parent / "Data" / "Input_data"
  ```
